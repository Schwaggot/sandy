# sandy

Run AI coding agents in sandboxed Docker containers, using your existing agent config.

```
cd my-project
sandy claude       # or: sandy pi / sandy opencode
```

See [docs/SPECIFICATION.md](docs/SPECIFICATION.md) for the full design.

## Install

macOS / Linux:

```
curl -fsSL https://raw.githubusercontent.com/schwaggot/sandy/main/scripts/install.sh | bash
```

Windows (PowerShell):

```
iwr -useb https://raw.githubusercontent.com/schwaggot/sandy/main/scripts/install.ps1 | iex
```

Requires Docker (recent version) on the host.

### Authenticate to ghcr.io

The agent and toolchain images live on GitHub Container Registry. If the
packages are private (the default for new packages, even when the repo
itself is public), Docker has to authenticate before `sandy pull` or
`sandy <agent>` can fetch them.

1. Create a personal access token at
   https://github.com/settings/tokens/new with the **`read:packages`**
   scope (classic tokens work; fine-grained tokens work too if you grant
   "Read access to packages").
2. Log in once per machine:

   ```
   echo 'ghp_YOUR_TOKEN' | docker login ghcr.io -u <user> --password-stdin
   ```

   Replace `<user>` with your GitHub username.

The credentials persist in `~/.docker/config.json`; you do not need to
repeat this until the token expires.

Alternatively, flip each `sandy-*` package to public visibility at
https://github.com/<user>?tab=packages and skip the login entirely.

### First-run notes

- **Claude Code (macOS host)**: the host client keeps OAuth credentials in
  the macOS keychain, which the container cannot read. On the first
  `sandy claude` you will be prompted to `/login`. After authenticating,
  `~/.claude/.credentials.json` lives in the bind-mounted config dir and is
  reused for subsequent runs.
- **Local model endpoints (LM Studio etc.)**: use `host.docker.internal` as
  the hostname in your agent config, not `127.0.0.1` or `localhost` (those
  refer to the container, not the host). Sandy already adds the host-gateway
  mapping so this just works.

## Usage

```
sandy init                 # detect toolchains; write .sandy/config.yaml
sandy <agent> [-- args]    # run an agent: pi | opencode | claude
sandy list agents          # list available agents
sandy list profiles        # list available profiles
sandy doctor               # check environment
sandy pull [agent]         # pre-pull images
sandy build                # build the project-local image from .sandy/Dockerfile
sandy clean                # remove this project's cache and home volumes
```

Flags: `--profile <name>`, `--runtime docker|podman`, `--dry-run`.

## Build from source

```
go build ./...
./sandy version
```

## Layout

- `~/.sandy/config.yaml` - user-level defaults (private endpoints, allowlist additions)
- `.sandy/config.yaml` - per-project (committed)
- `.sandy/Dockerfile` - optional, generated by `sandy init` for uncommon toolchain combinations

## Development

### Prerequisites

- Go 1.26+ (`brew install go` on macOS).
- Docker available locally for smoke-testing the runtime path.

### Repository layout

```
cmd/sandy/        # binary entry point (package main)
internal/         # private packages (not importable from outside the module)
  cli/            # cobra command tree
  config/         # 3-layer YAML config loader
  agent/          # agent manifest schema + loader
  profile/        # profile schema + loader
  project/        # project root, hash, toolchain detection
  runtime/        # Runtime interface + Docker shell-out
  sandbox/        # assembles a RunSpec from config + manifest + profile
  assets/         # //go:embed of bundled YAML
images/           # Dockerfiles (base, toolchains, agents)
scripts/          # install.sh, install.ps1
.github/workflows # CI, image builds, release
```

Tests live next to the code they cover as `*_test.go` files.

### Common commands

```
go mod tidy                    # sync go.mod/go.sum after changing imports
go build ./...                 # compile everything (no artifacts; type-check)
go build -o sandy ./cmd/sandy  # produce the sandy binary
go run ./cmd/sandy --help      # build and run in one step
go test ./...                  # run all tests
go test -run TestBuild ./internal/sandbox/   # run a single test
go vet ./...                   # static checks
gofmt -w .                     # format (also: goimports -w .)
```

### Adding a dependency

```
go get github.com/owner/pkg@latest
go mod tidy
```

`go.mod` and `go.sum` are both committed. CI verifies they are in sync (`go mod tidy` must produce no diff).

### Adding a new bundled agent or profile

1. Add `internal/assets/agents/<name>.yaml` (or `profiles/<name>.yaml`).
2. `embed.FS` picks it up automatically at the next build via the `//go:embed` directive in `internal/assets/assets.go`.
3. Add an image build entry under `images/agent-<name>/` and the matrix in `.github/workflows/images.yml` if it needs to be published.

### Dry-running container invocations

```
sandy --dry-run <agent>
```

prints the resolved `docker run` command without executing it. Useful when iterating on `internal/sandbox` or profile changes.

### Release

Tagging `vX.Y.Z` triggers `.github/workflows/release.yml`, which invokes goreleaser to cross-compile darwin/linux/windows × amd64/arm64 and publish a GitHub release.
